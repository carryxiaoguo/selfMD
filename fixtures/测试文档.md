## 明确不做的

列出来是为了说明**这些是取舍，不是遗漏**：

| 不做的事           | 原因                                                         |
| ------------------ | ------------------------------------------------------------ |
| 云同步、协作、账号 | 个人自用；引入账号体系会带来远超收益的复杂度                 |
| 插件系统           | 没有第三方开发者，插件 API 只会变成自己给自己加的约束        |
| 内置图床 SDK       | 图床协议五花八门，自己实现等于给每家写一个适配器；委托外部程序更稳 |
| PDF 排版模板       | Chromium 打印已经够用；精细排版交给专门的排版工具            |
| 多语言界面         | 只服务一个用户，翻译成别的语言没有意义                       |

## 已知限制

| 限制                           | 说明                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| 第三方主题只能部分迁移         | 基于**类名**的规则（`.md-fences`、`.md-image`…）能命中；基于**真实标签**的规则（`#write h1`）不会——编辑器产生的是 `div` 而非 `<h1>` |
| 拼写检查改语言后需重开文档     | Chromium 不会对已渲染的文本重新检查                          |
| 复制为图片有高度上限           | 8000px；超过会截断并**如实提示**，不静默给一张残缺的图       |
| 图表渲染依赖网络无关但依赖体积 | Mermaid 约 116 MB（node_modules），构建时间约 23 秒；它是动态引入的，纯文字文档不付这个启动成本 |
