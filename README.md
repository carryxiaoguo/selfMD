# selfMD

一款所见即所得的 Markdown 编辑器。个人自用，从零实现。

## 项目描述

**纯文本是唯一数据源。** 所有渲染——标题、代码块、表格、图片、公式、图表——都只是叠加在 Markdown 文本之上的视图层。保存到磁盘的永远是原始字节，一个字符都没被改写。这带来三个直接后果：

- 任何编辑器都能打开这些文件，任何版本控制都能正常 diff
- 渲染出问题不会损坏文档，最坏情况是"看起来像纯文本"
- 换掉这个编辑器，文件原样可用

### 功能

| 领域 | 内容 |
|---|---|
| **编辑器** | 实时预览（标记符号在非活动块收起、光标进入时露出源码）、源代码模式、完整块级与行内语法、GFM 扩展 |
| **代码块** | 围栏语法高亮；块内两个围栏始终可见，`Esc` 跳到块外 |
| **公式与图表** | KaTeX 渲染行内与块级公式；Mermaid 图表异步渲染，失败时保留源码 |
| **主题** | 三层级联；内置三款：黄皮纸（暖色纸感衬线）、月之亮面、月之暗面 |
| **文件** | 多文档标签（撤销历史各自独立）、快速打开、创建副本 / 重命名 / 移动到、自动保存与崩溃恢复 |
| **图片** | 粘贴 / 拖放 / 插入，四种存储策略，图床上传，右键菜单 10 项 |
| **导出** | HTML、PDF、复制为图片，经 Pandoc 支持 Word / LaTeX / ePub 等 |
| **界面** | 全中文、侧边栏三档显示策略、编辑器右键菜单、查找替换、拼写检查、专注与打字机模式 |

完整规格见 [`功能清单.md`](./功能清单.md)。

### 下载与运行

安装包与便携版见 [Releases](https://github.com/carryxiaoguo/selfMD/releases)。安装程序可以自选安装目录；便携版解压即用，不写注册表。

从源码运行：

```bash
pnpm install
pnpm dev        # 开发服务器 + Electron，带热更新
pnpm build      # 类型检查 + 生产构建到 out/
pnpm verify     # 全量验证
```

## 架构

**技术栈**：Electron + TypeScript + CodeMirror 6。

编辑器内核用 CodeMirror 而不是自研——它的状态模型（不可变状态 + 事务）天然适合"渲染层只读文档、绝不改文档"这套架构。

### 最要紧的一条决策：渲染层不改文档

CodeMirror 6 的文档内容与撤销历史都住在 `EditorState` 里。装饰层只做两件事：折叠标记符号、插入 widget。**所有"看起来像成品"的效果都不碰文本模型**，所以：

- 保存出去的一定是用户敲下的原文
- 渲染出错最坏是"显示不对"，不会写坏文件

### 目录

```
src/
├── shared/       主进程与渲染层共用：类型、IPC 契约、命令注册表、纯函数
├── main/         主进程：窗口、菜单、协议、IPC 处理器、导出、服务
├── preload/      contextBridge 桥接（未开 nodeIntegration）
└── renderer/
    ├── editor/         编辑器装配、命令、选区、智能标点
    │   └── live-preview/   实时预览装饰层
    ├── image/          图片解析、引用生成、插入、上传
    ├── ui/             侧边栏、大纲、偏好设置、上下文菜单
    └── styles/         设计令牌与基础样式
```

### 装饰层：两套机制，各有各的理由

| 机制 | 用途 | 为什么 |
|---|---|---|
| **ViewPlugin** | 行内标记折叠、行装饰、widget | 能拿到 `view.visibleRanges`，长文档只处理视口内容 |
| **StateField** | 块级替换（块级公式、Mermaid 图表） | **CodeMirror 禁止插件提供块级装饰**——插件属于视图层、随时可能销毁重建，而块级装饰会改变行的结构 |

这个约束是运行时抛异常，而渲染层的异常会被降级逻辑吞掉，界面上只表现为"没渲染出来"。只有端到端测试能抓到。

### 声明式设置表

偏好设置界面不硬编码任何一项，完全照着 `@shared/settings-schema.ts` 渲染。好处是**"表里的键是不是真的存在"可以被断言**——写成 `livePreveiw` 这种笔误时，界面照样画得出来、点下去毫无反应，靠肉眼几乎发现不了。

### 主题三层级联

`<主题>.css` → `base.user.css` → `<主题>.user.css`，后加载的优先，所以用户的自定义永远压在主题之上。主题链接在**运行时追加到 `<head>` 末尾**——构建工具会把自己打包的 CSS 注入到 head 末尾，静态写在前面的主题会被整个盖掉。

### 导出

HTML 与 PDF 自己渲染（遍历语法树生成 HTML，PDF 交给 Chromium 打印），其余格式委托 Pandoc。不自己写转换器：HTML 之外的格式各有各的规范，Pandoc 已经做到工业级。

### 验证

四层，共 **374 项断言**：

| 层 | 查什么 |
|---|---|
| **解析树计数** | 语法树里各类节点各有多少个，覆盖整篇文档 |
| **DOM 渲染计数** | 装饰是否真的落到 DOM 上，只覆盖视口 |
| **纯函数行为** | 智能标点、选区算法、图片路径解析、数学扫描、模糊匹配排序…… |
| **端到端链路** | 图片真的变成 `<img>`、公式与图表真的出图、多文档切换后改动不丢、导出文件真的生成 |

另有编码检查（UTF-8 / BOM / 乱码 / 行尾符）、中文化检查、品牌痕迹检查。

> **为什么计数要分两套**：解析树覆盖整篇文档，DOM 只覆盖视口——CodeMirror 会虚拟化长文档，视口外的行压根没有 DOM。两个数放在一起，才能区分"装饰没生效"和"内容在屏幕外"。
